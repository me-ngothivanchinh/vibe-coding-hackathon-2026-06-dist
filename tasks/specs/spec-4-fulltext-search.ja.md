# 仕様例: #4 議事録の本文を検索できない（全文検索）

> 言語: [English](spec-4-fulltext-search.md) | **日本語** | [Tiếng Việt](spec-4-fulltext-search.vi.md)

> これは「一例」です。合理的な別解釈で実装しても問題ありません。

## 受け入れ基準

1. 一覧画面に検索ボックスがあり、キーワードを入れて検索できる
2. **タイトルだけでなく本文 (`body`) も検索対象になる**
3. 大文字小文字を区別しない（"acme" でも "Acme" でも "ACME" でもヒットする）
4. 部分一致で検索される（"meet" で "meeting" にマッチ）
5. 空のクエリのときは全件表示される
6. 100 件規模のデータで体感レスポンスが「遅い」と感じない（数百ミリ秒以内目安）

## 想定される実装の方向性

### バックエンド

シンプル版（推奨、1.5h で間に合う）:

```ts
// GET /api/meetings?q=keyword
const where = q
  ? {
      OR: [
        { title: { contains: q, mode: 'insensitive' } },
        { body:  { contains: q, mode: 'insensitive' } },
      ],
    }
  : {}
const meetings = await prisma.meeting.findMany({ where, orderBy: { meetingDate: 'desc' } })
```

PostgreSQL の `ILIKE` 相当が走るので、100〜500 件規模なら index なしでも体感問題ない。

発展版（時間が余ったら）:

- PostgreSQL の `tsvector` / `tsquery` を使った全文検索
- スコアでソート（関連度順）
- 該当箇所のハイライト

ただし発展版は 1.5h では厳しいので、シンプル版で OK。

### フロントエンド

- 一覧画面の上部に `<input type="search">` を追加
- 入力するたびに API リクエスト（debounce 推奨、なくても可）
- クエリは URL の querystring に同期させて、リロードしても検索状態が保持されるようにすると良い
- 結果が 0 件のときに「該当する議事録はありません」と表示

UI 例:

```
┌────────────────────────────────────────┐
│ 🔍 [ acme                       ]  [×] │  ← 検索ボックス
├────────────────────────────────────────┤
│ Acme Q2 Kickoff                  4/15  │
│ Acme Renewal Discussion          4/10  │
│ ...                                    │
└────────────────────────────────────────┘
```

## 確認方法（参加者向け）

1. 既存 seed データに対して "search" と入れると、本文に "search" を含む議事録（Customer Feedback Discussion など）がヒットする
2. "ACME" と "acme" でヒット件数が同じ
3. 空文字にすると全 12 件が表示される
4. 何も該当しないキーワードで「該当する議事録はありません」が出る

## 評価ポイント

- バックエンド変更（API パラメータ追加）と UI 変更（検索ボックス）の両方が動く形になっているか
- スピード感：1.5h の枠内でシンプル版を選択できているか（最初から `tsvector` に手を出して時間切れになっていないか）
- 「検索結果が空のとき」のハンドリングがあるか

## 補足

- ソート順は既存と同じ `meetingDate desc` でよい
- ページネーションは本仕様では要求しない（500 件規模でも全件返してよい）
- 検索したキーワードを結果文中でハイライト表示するのは bonus（なくて OK）
